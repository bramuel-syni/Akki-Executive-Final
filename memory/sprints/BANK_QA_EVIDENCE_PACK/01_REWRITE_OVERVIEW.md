# 01 — Rewrite Overview

A five-paragraph briefing on the architecture and controls that ship with Akki today.

---

## Why this rewrite happened

The previous Akki codebase had fourteen separate call sites making direct LLM requests against OpenAI, Anthropic, and Gemini SDKs — Chat, Solva reasoning, Work Studio, Document Journal, Cycle Manager, Pulse, Monitor. Each call site implemented its own (mostly absent) de-identification, its own retry and timeout policy, and there was no single audit trail a regulator or internal auditor could point to. The four-day rewrite consolidates every outbound LLM request behind one gateway — Synisense Shield — that handles de-identification, audit logging, HMAC-signed trust receipts, purpose validation, and provider routing. The gateway is enforced by an automated continuous-integration guard so future development cannot accidentally bypass it. The architectural invariant is now: **no LLM call leaves the Akki process without passing through `synisense.shield.llm_router`.**

## Privacy by structure, not by promise

Synisense Shield runs local de-identification — a regex pass, then spaCy named-entity recognition, then a per-tenant Presidio recogniser — **before** any text reaches a third-party LLM. The de-identified text is what the provider sees. Re-identification (swapping back to surface names, monetary figures, email addresses to the user) happens locally on the response, after the LLM call returns. Every LLM call now emits two database records: a `synisense_audit_log` row carrying full pipeline metadata (provider, model, dilution score, exposure-reduction score, purpose, outcome) and a `synisense_trust_receipts` row carrying an HMAC-SHA256 signature over the canonicalised audit body, signed with a per-tenant key derived via HKDF from a master secret that the bank's deployment team controls. The tenant can recompute the HMAC themselves with their key and verify the chain — there is a standalone Python script in this evidence pack that does exactly this. The chat privacy-report PDF surfaces every audit row in natural-language prose alongside its full signature, so any tenant can pick any conversation, download the PDF, and verify it without server-side help.

## Single voice for the reasoning engine

Solva, Akki's structured reasoning engine, was rewritten from a two-engine "v2 plus Phase D" split into a single five-layer pipeline. The legacy `solva_v2` paths remain on disk for historical session display but no new session ever lands there; every Solva entry point (the landing page, the Cycle Manager handoff, the Work Studio handoff, the Document Journal handoff) routes into the new engine. The five layers — entry, framing audit, surfacing tensions, triangulation, synthesis — each call Shield under a dedicated purpose code (`solva.layer_0.frame_audit`, `solva.layer_1.coach_question`, and so on) so the same de-identification and audit chain applies to every reasoning step. A guardrail ladder of classifiers (jailbreak, therapy attempt, coaching-only request) sits at the entrance to Layer 1 and blocks anything that violates the product's hard limits. Refusals are routed through a single explainer path so every "I can't help with that" sentence is itself produced through Shield with an audit trail — nothing is hardcoded.

## Signals, not narratives, from the engine

The Synisense Engine produces signals only — never recommendations, never opinions, never narrative prose. Six categories are derived deterministically from real Mongo data: anomaly flags from cycle health, life-stage from session activity, churn risk from engagement composite, behavioural vector from action-log histograms, compliance trigger from regulatory-keyword scans on documents, and operational health from cycle and objective composites. No LLM is involved in signal production. Each signal carries a permanent `derivation_source` field — for example `derived_from_cycle_status_anomaly_cycles` — so it is distinguishable from the original Phase A seeded stubs and from any future ingested signals from external partners. The Monitor "Update goal" mechanic is the first consumer of these signals: when a user clicks "Update goal" on an objective or project, Akki queries the relevant signals plus the five most recent documents in the context, calls Shield with a constrained-JSON prompt, and persists the resulting status (on-track, at-risk, off-track) with the supporting rationale and the IDs of the signals it cited. The status is non-overridable; if the user disagrees, they must add a new signal-bearing event, not type over the conclusion.

## How a Bank QA reviewer validates the system end-to-end

The fastest end-to-end verification path is five steps. First, open the Admin → Synisense Observability page; the Activity tab shows live aggregate metrics across every consumer (Shield invokes, refusal rates, average dilution and exposure-reduction scores) and the Billing tab shows the per-consumer cost roll-up against a code-controlled pricing table. Second, open any chat conversation and click "Download privacy report" — the generated PDF carries one natural-language paragraph per turn and the full HMAC-SHA256 signature for each audit entry, with a verification recipe in the footer. Third, open the Monitor and click "Update goal" on any objective — the resulting assessment cites real engine signals by signal ID and carries a real audit ID, both of which can be cross-checked against the database. Fourth, run the standalone trust-receipt verification script (`04_TRUST_RECEIPT_VERIFICATION.py` in this pack) against any audit row and its receipt — the script outputs PASS or FAIL with the canonicalised payload, runnable with one command. Fifth, the test suite ships with 662 passing tests, including a continuous-integration guard test that grep-asserts no Python module outside `synisense/shield/llm_router.py` issues a direct LLM call. The full git commit history of the rewrite is preserved; each of the six phases (A through F.1) shipped its own closeout document under `/app/memory/sprints/` so the audit reviewer can trace every architectural decision back to the implementation that delivered it.
