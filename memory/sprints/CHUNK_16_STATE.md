## 2. Per-ID implementation notes

### QA-037 — Status badge per card

**Verbatim spec:** *"We are adding a status badge to every card to communicate lifecycle state at a glance. The three states from Chunk 8 are: Draft (text on neutral background) — work in progress, mutable; In Review (text on amber background) — pending review/sign-off; Committed (dark filled pill) — version-locked."*

**Implementation:** `components/work_studio/DocumentCardsSection.jsx::DocumentCardRow` renders a `<span data-testid="ws-document-card-status-{id}">` with palette from `BADGES`:
- `draft` → `bg-slate-100 text-slate-700` ("Draft")
- `in_review` → `bg-amber-50 text-amber-800` ("In Review")
- `committed` → `bg-slate-900 text-white` ("Committed" — dark filled per verbatim spec)

The dispatch's badge taxonomy decision lock (committed → "green chip") was overridden in favour of the QA-037 verbatim spec ("dark filled pill"). Divergence documented in §3 below.

### QA-038 — Lock icon overlay on Committed

**Verbatim spec:** *"A small lock icon is overlaid on the bottom-right corner of the document icon for Committed documents."*

**Implementation:** When `ls === "committed"`, render a `<span data-testid="ws-document-card-lock-{id}">` with a Lucide `Lock` icon, absolute-positioned at `-bottom-1 -right-1` on the document icon. Ring-2 white to visually separate the dark icon from the slate document glyph.

Gating: `isCommitted = ls === "committed"` — strict equality. Non-committed cards have ZERO lock icon DOM (verified by the render-smoke step 18 inverse assertion).

### QA-039 — Confidence chip with RAG colour

**Verbatim spec:** *"Confidence score: displayed as 'Confidence 87%'. Color coded: Above 75% — neutral; 50% to 75% — amber; Below 50% — red. The percentage is generated by Akki's intelligence module."*

**Implementation:** When `intel.confidence_pct` is a number, render `<span data-testid="ws-document-card-confidence-{id}">` with text `"Confidence {pct}%"`. Colour driven by the `confidence_band` field (returned by the listing endpoint, computed via the Chunk-8 `rag_band` helper).

The chip uses palette from `CONFIDENCE_CHIP_PALETTE`:
- `green` → `bg-emerald-50 text-emerald-800` (Chunk-8 threshold ≥80%)
- `amber` → `bg-amber-50 text-amber-800` (50% ≤ pct < 80%)
- `red` → `bg-rose-50 text-rose-800` (< 50%)
- `unrated` → `bg-slate-50 text-slate-600` (`confidence_pct === null`)

**Threshold divergence (Chunk 16 decision per dispatch's forgetting-mitigation protocol):** the dispatch said "≥80 green, 50-79 amber, <50 red" (Chunk-8 thresholds). QA-039 verbatim says "Above 75% neutral, 50-75% amber, Below 50% red". I followed the dispatch (Chunk-8 thresholds) to keep consistency with the existing `rag_band` helper used elsewhere in Work Studio. Divergence documented in §3.

### QA-040 — Persistent download icon

**Verbatim spec:** *"A download icon is added as a persistent action on every card regardless of lifecycle state. The download produces the document in its source format. If the document was generated as a DOCX it downloads as DOCX. If it was generated as a PDF it downloads as PDF."*

**Implementation:** `<button data-testid="ws-document-card-download-{id}">` always renders, never gated by lifecycle state (verified statically by `test_chunk16_qa040_download_button_visible_on_all_states`).

Download flow (2 steps):
1. `GET /api/contexts/{cid}/work-studio/exports/{eid}` returns `download_token` for export rows with `status === "complete"`.
2. `GET /api/contexts/{cid}/work-studio/exports/{eid}/download?token=…` opens in a new tab. Server streams with the original `Content-Disposition` + source MIME (per `work_studio_export.py:1577+`).

For rows without a `download_token` (e.g. export `status !== "complete"`), the click surfaces a friendly toast: *"This document doesn't have a downloadable export yet. Compile the underlying source artefact first."* — no raw 4xx leak.
