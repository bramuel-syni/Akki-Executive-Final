## What this means

FastAPI builds the OpenAPI schema by composing each route's
function name + path into a unique `operation_id`. When two
routes resolve to the same `operation_id` (typically because a
function name is reused across two router files, or a route is
registered twice via `include_router()`), FastAPI logs the
duplicate and keeps the FIRST one in the OpenAPI spec; the
second still works at runtime but is invisible to OpenAPI
consumers.

## Impact assessment

- ✅ Every route still mounts and serves traffic.
- ✅ `/api/openapi.json` is generated successfully (the warning is
  emitted but not raised).
- ✅ No runtime 4xx/5xx are produced by this warning class.
- ⚠️ OpenAPI schema is incomplete — the "lost" duplicate routes
  are missing from machine-readable API docs. Affects code-gen
  tooling and the autogenerated `/docs` Swagger UI, but NOT the
  app itself.

## Cleanest fix (FOR A LATER DISPATCH — NOT this one)

For each duplicate:
1. Cite the two routes that collide on the same `operation_id`.
2. Decide whether one is genuinely redundant (delete) or just
   needs a unique `operation_id=` keyword on the `@router.get(…)`
   decorator.
3. Apply.
4. Regression-check that the production OpenAPI schema is now
   warning-free.

Estimated impact: ≤5 decorator edits + a startup-warning
lockdown test. Not enough product value to justify a dedicated
dispatch right now; surfaces here so the next agent or
maintenance window can pick it up.
